# ProofPick

## 秘密のまま、いっしょに買う。

注文を見せずに合計を計算し、正しさを確かめて共同購入へ。

<div class="pt-8 text-sm opacity-70">全国情報教育コンテストに向けたプロトタイプ</div>

---

# 共同購入には、注文を集める人が必要だった。

- **参加者**：欲しい数量や予算を、取りまとめ役に知られたくない。
- **取りまとめ役**：個別の注文を預かり、計算と管理の責任を負う。
- **販売者**：合計が成立条件を満たすか、正しく確認したい。

想定する場面：学校・地域・小さなお店などの共同購入。

---

# 個別の数量を隠したまま、合計と成立条件を確かめる。

分散 ID でログイン → 注文を暗号化 → 秘密集計 → 証明・検証 → 成立後に発注

販売者は、成立後に商品を用意するため、個別注文を開きます。

<div class="text-sm opacity-70 mt-8">分散 ID の接続は試用版。IdP を含む一連の動作確認は未実施です。</div>

---

# 認証と注文の権限をつなげる。

- 参加者の端末は、分散 ID でログインし、端末の鍵で API ごとに証明を作る。
- 分散 IdP は、複数ノードによる認証と署名でトークンを発行する。
- ProofPick はトークンと端末鍵を確認し、注文を ID と秘密コードに結びつける。

<div class="text-sm opacity-70 mt-8">PASTA / FROST、OAuth 認可コード、DPoP を利用。主催者・販売者の秘密コードは引き続き必要です。</div>

---

# 数量を分けて預け、合計だけを計算する。

1. **秘密分散**：端末で数量を分けて暗号化し、3者それぞれへ送る。
2. **REP3**：個別数量を復元せず、合計・金額・成立条件を計算する。
3. **Groth16**：登録した注文と条件に対応する計算結果かを検証する。

<div class="text-sm opacity-70 mt-8">認証の3ノードと、共同購入の計算に使う3者は別の仕組みです。</div>

---

# 3件の注文を集計し、発注まで進めた。

数量 **2・3・4** を秘密のまま計算。

## 合計 9個 / 1,620円

Groth16 証明を別実装で検証し、発注・受け取りまで記録。成立数量が10個の場合は発注を止めました。

<div class="text-sm opacity-70 mt-8">共同購入の検証結果です。分散 IdP 接続後の通し動作は未確認です。</div>

---

# 必要な人に、必要な情報だけ。

- **参加者**：自分の注文を操作。予算は端末内で確認し、送信しない。
- **主催者**：進行と合計を確認。個別数量は表示しない。
- **販売者**：証明の検証後に個別注文を開き、商品を用意する。

<div class="text-sm opacity-70 mt-8">合計・金額・成立条件・注文件数などは公開します。少人数の場合、合計から個別数量を推測される可能性があります。</div>

---

# 実証できた範囲を、そのまま伝える。

**確認できたこと**：同一 PC 上の3者による秘密集計、証明生成・検証、発注と受け取りの記録。

**これから確かめること**：分散 IdP と共同購入の通し動作、実際の利用者による操作、独立した組織での運用。

<div class="text-sm opacity-70 mt-8">OS・管理者と開発用の証明パラメータを信頼する試用版。実決済・配送は未接続、受け取りは本人申告です。</div>

---

# 安心して使える共同購入へ、試して改善する。

1. **通し動作を検証**：分散 ID のログインから受け取りまで確認する。
2. **使う人に試してもらう**：見える情報と操作の分かりやすさを観察する。
3. **運用の条件を整える**：鍵の管理、HTTPS、独立ノードなどに取り組む。
